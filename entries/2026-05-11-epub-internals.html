01

EPUB とは何か

overview

EPUB は 「リフロー可能な電子書籍」のためのオープン標準。Kindle 専用の AZW/MOBI/KFX とは異なり、 Apple Books / Google Play Books / 楽天 Kobo / 各種読書アプリが共通して扱える。中身は基本的に Web 技術 （XHTML 5、CSS、SVG、JavaScript）で構成されており、「本」を「Web ページの集合体」として扱う設計思想です。

初版リリース2007EPUB 2.0
最新版3.32023-05 W3C Rec.
中核フォーマットXHTML+ CSS / SVG
梱包形式ZIPOCF コンテナ
i

核心はとてもシンプル

.epub ファイルの拡張子を .zip にリネームして ダブルクリックすれば、普通に解凍できます。中から出てくるのは XHTML ファイル、CSS、画像、それと 「目次」と「読む順序」を記述した XML——たったそれだけ。

02

仕様の 3 層構造

OCF · OPF · Content

EPUB の規格は責務ごとに 3 層に分離されています。「入れ物（コンテナ）」「目録（パッケージ）」「中身（コンテンツ）」 の分離は、Web の URL/HTTP/HTML の分離と相似です。

03

メタデータ・ファイル一覧（manifest）・読む順序（spine）・ナビゲーションを記述。
content.opf · nav.xhtml

03

典型的なファイル構成

unzip 直後の中身

`.epub` を解凍すると、おおむね下のようなツリーが現れます。必須 は規格上絶対に必要なもの、 慣習 は実装上ほぼ存在するもの。

my-book.epub/ ├── mimetype 必須・無圧縮 STORE 方式・先頭に配置 ├── META-INF/ │ └── container.xml 必須・OPF への入り口 ├── OEBPS/ 慣習的なルートディレクトリ名（任意） │ ├── content.opf 必須・パッケージ本体 │ ├── nav.xhtml EPUB 3 必須・目次（XHTML） │ ├── toc.ncx EPUB 2 互換目次（後方互換） │ ├── text/ │ │ ├── cover.xhtml │ │ ├── chap01.xhtml 本文 ── 章ごとに分割 │ │ └── chap02.xhtml │ ├── styles/ │ │ └── style.css │ ├── images/ │ │ ├── cover.jpg │ │ └── fig01.png │ └── fonts/ │ └── NotoSerifJP-Regular.otf 埋め込みフォント（任意）
!

mimetype は特別扱い

mimetype ファイルは ZIP の最初のエントリかつ無圧縮（STORE 方式） で格納する必要があります。これは ZIP の先頭バイトを覗くだけで「これは EPUB だ」と判別できるようにするためで、 EPUB 特有の作法です。

04

mimetype

20 bytes

ファイル全体は実質これ 1 行のテキスト。中身は固定文字列。 

application/epub+zip

改行なし・BOM なし・余計なホワイトスペースなし。先頭 30 バイトを読むだけでファイル判定できる仕組みです。

05

META-INF/container.xml

EPUB の入り口

リーダーアプリは ZIP を開いたら最初にこのファイルを読み、`rootfile` 属性が指す場所（OPF）を探しに行きます。 つまり、本体 OPF の置き場所を宣言するだけの「玄関」です。 

<?xml version="1.0"?>
<container version="1.0"
           xmlns="urn:oasis:names:tc:opendocument:xmlns:container">
  <rootfiles>
    <rootfile full-path="OEBPS/content.opf"
              media-type="application/oebps-package+xml"/>
  </rootfiles>
</container>
06

OPF パッケージ

本の目録

OPF（Open Packaging Format）は EPUB の「中枢」。3 つのセクションから成ります。 これを理解すれば EPUB の構造はほぼ理解したと言えます。

セクション役割例
<metadata> タイトル・著者・言語・ISBN・出版日など書誌情報。Dublin Core スキーマを使用。 dc:title, dc:creator
<manifest> 本に含まれるすべてのファイルの一覧。各ファイルに id と MIME タイプを付与。 item id="..." href="..."
<spine> manifest 内のファイルのうち、本文として何をどの順序で読むかを定義。 itemref idref="chap01" 
<?xml version="1.0" encoding="UTF-8"?>
<package xmlns="http://www.idpf.org/2007/opf" version="3.0" unique-identifier="BookId">

  <!-- ① 書誌情報 -->
  <metadata xmlns:dc="http://purl.org/dc/elements/1.1/">
    <dc:identifier id="BookId">urn:isbn:978-4-12-345678-9</dc:identifier>
    <dc:title>EPUB の内部構造</dc:title>
    <dc:creator>今枝 俊治</dc:creator>
    <dc:language>ja</dc:language>
    <meta property="dcterms:modified">2026-05-11T00:00:00Z</meta>
  </metadata>

  <!-- ② ファイル一覧 -->
  <manifest>
    <item id="nav"    href="nav.xhtml"        media-type="application/xhtml+xml" properties="nav"/>
    <item id="cover"  href="text/cover.xhtml"  media-type="application/xhtml+xml"/>
    <item id="chap01" href="text/chap01.xhtml" media-type="application/xhtml+xml"/>
    <item id="css"    href="styles/style.css"   media-type="text/css"/>
    <item id="img1"   href="images/cover.jpg"   media-type="image/jpeg" properties="cover-image"/>
  </manifest>

  <!-- ③ 読む順序 -->
  <spine>
    <itemref idref="cover"/>
    <itemref idref="chap01"/>
  </spine>

</package>
i

spine の重要性

manifest にあっても spine に含まれない XHTML はリーダー上で本文として表示されません （リンク先として参照される補助的なページなどに使われます）。「本のリニアな読み進め順」を決めているのは spine です。

07

ナビゲーション（目次）

nav.xhtml / toc.ncx

EPUB 3 の目次は普通の XHTML。<nav epub:type="toc"> 属性が付いた要素を リーダーが「目次」として認識するだけ。EPUB 2 は別言語の toc.ncx を使っていましたが、 EPUB 3 で本文と同じ言語に統合されました。 

<!DOCTYPE html>
<html xmlns="http://www.w3.org/1999/xhtml" xmlns:epub="http://www.idpf.org/2007/ops">
<head><title>目次</title></head>
<body>
  <nav epub:type="toc" id="toc">
    <h1>目次</h1>
    <ol>
      <li><a href="text/cover.xhtml">表紙</a></li>
      <li><a href="text/chap01.xhtml">第 1 章 EPUB とは</a></li>
      <li><a href="text/chap02.xhtml">第 2 章 内部構造</a></li>
    </ol>
  </nav>
</body>
</html>
08

本文 XHTML

中身は Web ページ

本文は XHTML 5（XML として整形式である必要がある HTML5）。CSS / SVG / 画像 / フォントが普通に使え、 JavaScript も EPUB 3 から正式サポート（リーダーによる）。要するに「リーダー＝ブラウザ」。 

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE html>
<html xmlns="http://www.w3.org/1999/xhtml" xml:lang="ja">
<head>
  <meta charset="utf-8"/>
  <title>第 1 章</title>
  <link rel="stylesheet" href="../styles/style.css"/>
</head>
<body>
  <h1>第 1 章 EPUB とは</h1>
  <p>EPUB は ZIP に詰め込まれた XHTML である。</p>
  <figure>
    <img src="../images/fig01.png" alt="構造図"/>
    <figcaption>図 1: 3 層構造</figcaption>
  </figure>
</body>
</html>
!

HTML5 ではなく XHTML 5

通常の HTML5 と違い、すべてのタグを閉じる必要があります（<br/>、 <img .../>）。これは XML パーサで処理されるためで、不正な構文だと 本が開けないことがあります。検証には EPUBCheck を使うのが定番です。

09

レイアウト方式

reflowable / fixed

EPUB の最大の特徴は リフロー（reflowable）——画面サイズや文字サイズに応じてテキストが自動的に 折り返されること。一方で、漫画や絵本のようにレイアウト固定が必要な場合は Fixed Layout EPUB（FXL） モードを選びます。

方式用途OPF での宣言挙動
Reflowable 小説・新書・実用書（テキスト主体） 未指定（既定） 文字サイズ・画面サイズで折り返し
Fixed Layout 漫画・絵本・写真集・雑誌 rendition:layout = pre-paginated ページが固定。viewport 必須 
<!-- 固定レイアウト宣言（OPF metadata 内） -->
<meta property="rendition:layout">pre-paginated</meta>
<meta property="rendition:orientation">portrait</meta>
<meta property="rendition:spread">landscape</meta>

<!-- 各 XHTML 側 -->
<meta name="viewport" content="width=1200, height=1800"/>
10

固定レイアウト EPUB の作り方

FXL · 漫画 / 絵本

漫画・絵本・写真集・雑誌のように「ページ」という単位そのものが意味を持つ本では、リフローでは 崩れてしまいます。Fixed Layout EPUB（FXL）は、1 ページ = 1 XHTML ファイルとして、ピクセル単位で レイアウトを固定する方式。Web で言えば「印刷物の PDF を XHTML で再現する」イメージです。

手順 1 — OPF のメタデータで FXL モードを宣言

<metadata>
  <!-- 固定レイアウト宣言 -->
  <meta property="rendition:layout">pre-paginated</meta>
  <meta property="rendition:orientation">auto</meta>
  <meta property="rendition:spread">landscape</meta>
</metadata>
プロパティ値意味
rendition:layoutreflowable / pre-paginatedレイアウト方式の宣言。FXL は pre-paginated
rendition:orientationauto / landscape / portrait強制する画面の向き（auto は端末任せ）
rendition:spreadnone / landscape / both見開き表示の有無。漫画は通常 landscape

手順 2 — spine で右綴じ / 左綴じを指定

<!-- 漫画など右綴じの本 -->
<spine page-progression-direction="rtl">
  <itemref idref="p001" properties="page-spread-right"/>
  <itemref idref="p002" properties="page-spread-left"/>
  <itemref idref="p003" properties="page-spread-right"/>
  <itemref idref="p004" properties="page-spread-left"/>
</spine>

page-progression-direction はページが進む方向（rtl = 右綴じ・右から左へ、 ltr = 左綴じ・左から右へ）。page-spread-left/right は見開き表示時に そのページが左右どちらに来るかの宣言で、表紙の次のページから交互に指定します。

手順 3 — 各 XHTML に viewport を指定

<!-- text/p001.xhtml — 1 ページ 1 ファイル -->
<!DOCTYPE html>
<html xmlns="http://www.w3.org/1999/xhtml">
<head>
  <meta charset="utf-8"/>
  <!-- ★ FXL の心臓部：ページサイズを宣言 -->
  <meta name="viewport" content="width=1200, height=1800"/>
  <title>p001</title>
</head>
<body style="margin:0;">
  <!-- 画像 1 枚を全面に貼る漫画方式 -->
  <img src="../images/p001.jpg" alt="" width="1200" height="1800"/>
</body>
</html>
!

viewport の width/height は揃える

すべての XHTML で 同じ viewport サイズを指定するのが鉄則です。ページごとにサイズが違うと、 リーダーが拡大率を毎ページ変えてしまい、読書体験が破綻します。漫画は B6 比率の 1200×1800 が定番、A5 サイズなら 1500×2100 程度が よく使われます。

i

画像方式 vs テキスト方式

漫画は 1 ページ = 画像 1 枚が一般的（テキスト検索や文字拡大は犠牲になるが、レイアウトが完全に保てる）。 一方、絵本や雑誌で文字検索を残したい場合は、画像と XHTML テキストを CSS の position: absolute で重ねる「ハイブリッド方式」も使われます。 このときは Apple Books の独自拡張 com.apple.ibooks.display-options を併用すると挙動が安定します。

11

日本語縦書き CSS

writing-mode · ruby · 縦中横

EPUB 3 の日本語縦書きは CSS Writing Modes Level 3 がベース。writing-mode 一行で 文字組みが回転し、ルビ・圏点・縦中横といった日本語特有の組版を CSS と HTML で表現できます。 Web 標準の機能なので、Safari / Chrome でもそのまま動きます。

基本 — writing-mode と spine の方向

/* CSS — body 全体を縦書きに */
html {
  writing-mode: vertical-rl;   /* 縦書き・右から左 */
  -epub-writing-mode: vertical-rl; /* 古いリーダー互換 */
  font-family: "Hiragino Mincho ProN", "YuMincho", serif;
  line-height: 1.8;
}
<!-- OPF — 縦書きの本は spine も右綴じに -->
<spine page-progression-direction="rtl">
  <itemref idref="chap01"/>
</spine>
writing-mode 値意味用途
horizontal-tb横書き・上から下（既定）欧文・横組み和文
vertical-rl縦書き・右から左へ進行日本語の小説（最も一般的）
vertical-lr縦書き・左から右へ進行モンゴル語など特殊用途

ルビ — HTML5 標準タグ

<!-- 漢字にふりがなを振る -->
<p>
  <ruby>電子書籍<rt>でんししょせき</rt></ruby>の標準フォーマット
</p>

<!-- モノルビ（一字ずつ振る） -->
<p>
  <ruby>電<rt>でん</rt>子<rt>し</rt>書<rt>しょ</rt>籍<rt>せき</rt></ruby>
</p>

<!-- 非対応リーダー向けに rp で囲んでフォールバック -->
<ruby>仮名<rp>（</rp><rt>かな</rt><rp>）</rp></ruby>

<rt> はルビ本体（フリガナ）、<rp> は 非対応環境で「（ ）」のような括弧として表示されるフォールバック文字。EPUB 3 標準対応で、リフロー / FXL 双方で動作します。

圏点（傍点） — text-emphasis

.emphasis {
  -webkit-text-emphasis-style: filled sesame;  /* ゴマ点 */
  text-emphasis-style:         filled sesame;
  -webkit-text-emphasis-position: over right;   /* 縦書き時は右側 */
  text-emphasis-position:         over right;
}
<p>これは<span class="emphasis">絶対に</span>大事だ。</p>

小説で「ここを強調したい」ときに使う傍点。filled（黒丸）/ open（白丸） × dot / circle / sesame（ゴマ点）/ triangle の組み合わせから選べます。

縦中横 — text-combine-upright

.tcy {
  -webkit-text-combine:        horizontal;   /* WebKit 旧仕様 */
  text-combine-upright:         all;          /* 標準 */
}
<p>昭和<span class="tcy">64</span>年は短かった。</p>
<p>第<span class="tcy">12</span>巻発売中。</p>

縦書きの中で 2〜3 桁の数字や英字を横に並べて 1 マスに収める組版。text-combine-upright: all を当てると、内側のテキスト全体が「1 文字分の正方形」に押し込められます。日付・巻数・章番号でよく使う表現。

英数字の向き — text-orientation

/* 縦書きでも英数字を横向きのまま回転させない */
.upright {
  text-orientation: upright;
}

/* 既定: mixed = 全角は縦・半角英数は 90° 回転（横向き）で配置 */
html {
  writing-mode: vertical-rl;
  text-orientation: mixed;  /* 既定値 */
}
text-orientation 値挙動用途
mixed全角は縦、半角英数は横向き（既定）標準の縦書き本文
uprightすべての文字を縦に立てる英字も縦に並べたい特殊組版
sideways文字全体を 90° 回転欧文タイトルなど
!

3 つの "方向" が連動する

縦書き本では (1) CSS の writing-mode: vertical-rl、(2) OPF spine の page-progression-direction="rtl"、(3) HTML 要素の dir="rtl" あるいは lang="ja" ——この 3 段が揃って初めて期待通りの挙動になります。CSS だけ縦書きにしても、ページめくりが 横書き方向（左→右）のままだと違和感が出るので注意。

完成形 — 小説の冒頭 1 ページ

<!DOCTYPE html>
<html xmlns="http://www.w3.org/1999/xhtml" xml:lang="ja" lang="ja">
<head>
  <meta charset="utf-8"/>
  <title>第一章</title>
  <style>
    html { writing-mode: vertical-rl; font-family: "游明朝", serif; }
    body { line-height: 1.8; margin: 2em; }
    h1   { font-size: 1.4em; margin-bottom: 2em; }
    .tcy { text-combine-upright: all; }
    em   { font-style: normal; text-emphasis: filled sesame; }
  </style>
</head>
<body>
  <h1>第<span class="tcy">01</span>章</h1>
  <p>
    <ruby>吾輩<rt>わがはい</rt></ruby>は<em>猫</em>である。
    名前はまだ無い。
  </p>
</body>
</html>
✓

ブラウザで確認できる

このコードはそのまま .html として保存して Safari / Chrome で開けば、 EPUB リーダーなしでもレンダリング結果が確認できます。EPUB 化前のレイアウト調整は、ブラウザで イテレーションするのが最速です。

EPUB 2 と EPUB 3 の違い

主要な変更点

現代の EPUB はほぼ EPUB 3 系（3.0 → 3.0.1 → 3.2 → 3.3）。EPUB 2 は 2007 年の規格ですが、互換性のため いまも併存することがあります。

日本語縦書きは EPUB 3 から

EPUB 3.0 で writing-mode: vertical-rl や HTML5 ruby が正式採用され、 日本の出版社が EPUB を本格採用するきっかけになりました。日本語コンテンツは原則 EPUB 3 と考えてよいです。

13

DRM（デジタル著作権管理）

仕様の "上" のレイヤー

DRM は EPUB 仕様の本体に含まれません。OCF コンテナの仕様には META-INF/encryption.xml という「暗号化されたファイルを記述する場所」だけが 規定されており、暗号化方式そのものは各社バラバラ。だから「EPUB は DRM フリー」とも 「EPUB は DRM 付き」とも言える両義的な状態です。

主要 DRM 方式の比較

方式採用ストア特徴
Adobe ADEPT Kobo · 旧 NOOK · 多くの欧米書店 業界デファクト。Adobe ID で端末紐付け。Adobe Digital Editions 経由で読む
Apple FairPlay Apple Books Apple ID と端末紐付け。完全に閉じた独自実装
Readium LCP EDRLab 主導 · 仏英の公共図書館 オープン仕様の DRM。パスフレーズ認証で端末数制限なし。最近採用が拡大中
Marlin BookLive! など日本系 Intertrust 製。日本の電子書店で採用例あり
Social DRM O'Reilly · 技術書出版社 暗号化せず、購入者情報を電子透かしで埋め込む "ゆるい DRM"
Amazon (KFX/AZW) Kindle ※そもそも EPUB ではなく独自フォーマット。EPUB を入稿しても KFX に変換される

META-INF/encryption.xml の例

<?xml version="1.0"?>
<encryption xmlns="urn:oasis:names:tc:opendocument:xmlns:container"
            xmlns:enc="http://www.w3.org/2001/04/xmlenc#">
  <enc:EncryptedData>
    <enc:EncryptionMethod
      Algorithm="http://www.w3.org/2001/04/xmlenc#aes256-cbc"/>
    <enc:CipherData>
      <enc:CipherReference URI="OEBPS/text/chap01.xhtml"/>
    </enc:CipherData>
  </enc:EncryptedData>
</encryption>

この XML が示すのは「chap01.xhtml は AES-256-CBC で暗号化されている」という事実だけ。 復号鍵の取得方法（ストアサーバへの認証など）は仕様外で、各 DRM ベンダの独自プロトコルです。

フォントの難読化（Font Mangling）

<!-- IDPF Font Obfuscation -->
<enc:EncryptedData>
  <enc:EncryptionMethod
    Algorithm="http://www.idpf.org/2008/embedding"/>
  <enc:CipherData>
    <enc:CipherReference URI="OEBPS/fonts/NotoSerifJP.otf"/>
  </enc:CipherData>
</enc:EncryptedData>
i

埋め込みフォントだけは "ほぼ全 EPUB" に DRM がかかる

商用フォントを EPUB に埋め込む場合、フォントベンダのライセンス上、難読化が必須な ことが多く、本文に DRM をかけない技術書でもフォントだけは encryption.xml で http://www.idpf.org/2008/embedding 方式で難読化されます。これは "意味のある暗号化" ではなく、「直接フォントファイルを抜き出されないようにする」程度の措置。

14

Media Overlays（音声同期）

SMIL · Read Aloud

Media Overlays は、本文テキストと音声ナレーションを同期再生する EPUB 3 の機能。 語学学習書、視覚障害者向けアクセシブル本、読み聞かせ絵本などで使われます。同期記述には SMIL（Synchronized Multimedia Integration Language）という別の XML 言語を使用します。

仕組みの全体像

SMIL ファイルの中身

<?xml version="1.0" encoding="UTF-8"?>
<smil xmlns="http://www.w3.org/ns/SMIL"
      xmlns:epub="http://www.idpf.org/2007/ops"
      version="3.0">
  <body>
    <seq id="chap01" epub:textref="chap01.xhtml" epub:type="chapter">

      <par id="par1">
        <text  src="chap01.xhtml#p001"/>
        <audio src="audio/chap01.mp3" clipBegin="0:00:00.000" clipEnd="0:00:03.500"/>
      </par>

      <par id="par2">
        <text  src="chap01.xhtml#p002"/>
        <audio src="audio/chap01.mp3" clipBegin="0:00:03.500" clipEnd="0:00:07.200"/>
      </par>

    </seq>
  </body>
</smil>

<par>（parallel）が同期の最小単位。「この text と この audio は並行して再生される」 という意味で、リーダーは音声再生に合わせて該当テキストをハイライトします。

OPF 側での結びつけ

<manifest>
  <!-- 本文 XHTML に media-overlay 属性で SMIL を紐付け -->
  <item id="chap01"      href="text/chap01.xhtml"
        media-type="application/xhtml+xml"
        media-overlay="chap01-smil"/>
  <item id="chap01-smil" href="text/chap01.smil"
        media-type="application/smil+xml"/>
  <item id="audio01"     href="audio/chap01.mp3"
        media-type="audio/mpeg"/>
</manifest>

<metadata>
  <!-- 全本の総再生時間（必須） -->
  <meta property="media:duration">0:24:35</meta>
  <!-- ハイライト表示用の CSS クラス -->
  <meta property="media:active-class">-epub-media-overlay-active</meta>
</metadata>
✓

絵本やアクセシビリティで強い武器

Apple Books の "Read Aloud"、児童書の "読み聞かせモード"、視覚障害者向けの DAISY 規格との橋渡しなど、 応用範囲が広い機能です。一方、対応リーダーが限定的（Apple Books と一部専用アプリのみ実用レベル） なのが現状の弱点。

15

Apple Books の独自拡張

com.apple.ibooks.*

Apple Books（旧 iBooks）は EPUB の "拡張パイオニア" として、仕様外の独自メタデータや CSS プロパティを 多数追加してきました。多くは 後に EPUB 3 標準に取り込まれたもの（縦中横、テキストエンファシスなど）。 ただし現在も Apple Books でしか動かない独自機能はいくつか残っています。

META-INF/com.apple.ibooks.display-options.xml

<?xml version="1.0" encoding="UTF-8"?>
<display_options>

  <!-- iPad / iPhone 共通設定 -->
  <platform name="*">

    <!-- 埋め込みフォントを使う宣言（重要） -->
    <option name="specified-fonts">true</option>

    <!-- 固定レイアウト宣言（旧 iBooks 形式） -->
    <option name="fixed-layout">true</option>

    <!-- 表紙を見開きで表示せず単独ページに -->
    <option name="open-to-spread">false</option>

    <!-- インタラクティブ要素を許可 -->
    <option name="interactive">true</option>

  </platform>

  <!-- iPhone のみの設定も可能 -->
  <platform name="iphone">
    <option name="orientation-lock">portrait-only</option>
  </platform>

</display_options>
オプション意味備考
specified-fonts埋め込みフォントを優先利用これを true にしないと Apple Books はシステムフォントで上書きする
fixed-layout固定レイアウト宣言EPUB 3 の rendition:layout と二重に書くのが慣習
open-to-spread表紙を単独表示するか漫画では false 推奨（表紙単独 → 中身は見開き）
interactiveJS / インタラクティブ要素の許可EPUB 3 では本来不要だが、古い iBooks 互換のため
orientation-lock画面の向きを固定portrait-only / landscape-only

独自 CSS / メタデータ

/* Apple Books 独自の本文配色制御 */
html {
  -webkit-text-size-adjust: none;        /* 文字サイズ自動調整を抑止 */
}

/* ナイトモード時の色を上書きさせない */
.cover {
  -webkit-color-correction: srgb;
}
<!-- OPF metadata -->
<meta property="ibooks:version">1.1.0</meta>
<meta property="ibooks:specified-fonts">true</meta>
<meta property="ibooks:binding">true</meta>     <!-- 製本見せ -->
<meta property="ibooks:scroll-axis">vertical</meta>
<meta property="rendition:layout">pre-paginated</meta>
!

display-options.xml は "保険" として今も書く

EPUB 3 標準の rendition:* プロパティだけで本来は十分ですが、 古い iBooks（iOS 8 以前）が EPUB 3 を完全には理解しないため、出版社の入稿要件として display-options.xml の併記が今も必須なケースが残っています。Apple 公式の "iBooks Asset Guide" で形式が定義されています。

リーダーアプリの実装差異

主要 5 プラットフォーム

EPUB 仕様は厳密ですが、リーダーアプリの実装は仕様の解釈と対応範囲がバラバラ。 "Web のクロスブラウザ問題" と同じ構造で、出版社の現場では「Apple Books で確認 → Kobo で確認 → Kindle で確認」という 多段テストが日常的です。

対応状況の比較マトリクス

機能 Apple Books Kobo Google Play Books Kindle

固定レイアウト（FXL） 良好 良好 限定的 変換
縦書き（vertical-rl） 良好 良好 部分 良好
ルビ 完全 完全 部分 完全
JavaScript 対応 無効化 無効化 無効化
Media Overlays 対応 非対応 非対応 非対応
埋め込みフォント 要宣言 対応 対応 置換あり
独自フォーマット変換 EPUB のまま EPUB のまま EPUB のまま KFX へ変換

レンダリングエンジン

リーダーエンジン挙動の傾向

!

Kindle は EPUB ではない（実質的に）

Kindle Direct Publishing には .epub を入稿できますが、Amazon サーバが KFX という独自フォーマットへ自動変換します。この変換の過程で CSS の一部が無視されたり、 FXL の見開きが崩れたりするので、Kindle 向けには 必ず Kindle Previewer で再確認するのが鉄則です。

i

「最大公約数」で書く戦略

実用上は最も対応が悪いリーダーを基準に書くのが安全。具体的には 「JavaScript を使わない」「複雑な CSS（grid, flexbox の入れ子, custom properties）を避ける」 「Apple 独自拡張は併記する」という保守的方針を取ると、5 プラットフォーム横断で破綻しにくくなります。

17

触って確かめるためのツール

macOS で使えるもの

実際に EPUB を分解・作成・検証するための定番ツールを挙げます。手を動かすのが一番理解が早いです。

  1. unzip / Finder で解凍：手元にある .epub をコピーして拡張子を .zip にすれば中身が見える。EPUB の正体を実感する最短ルート。
  2. EPUBCheck：W3C 公式の検証ツール（Java）。brew install epubcheck で入る。仕様違反をエラーで教えてくれる。
  3. Sigil：オープンソースの EPUB 専用エディタ。WYSIWYG ではなくコード編集寄り。GUI で manifest や spine を弄れる。
  4. Calibre：電子書籍管理アプリ。MOBI/AZW3 ⇄ EPUB 変換、メタデータ編集、リーダー機能を兼備。
  5. Apple Books：macOS 標準。手元の .epub をダブルクリックすれば読める。リファレンス実装的に挙動が見られる。
  6. Pandoc：Markdown ↔ EPUB の相互変換が可能。pandoc input.md -o book.epub の 1 行で生成できる。EPUB 入門に最適。
i

まず Pandoc で 1 つ作ってみる

手持ちの Markdown があれば pandoc README.md -o test.epub だけで EPUB が作れます。 その test.epub を .zip に改名して解凍すれば、 ここまで説明したファイル構造がそのまま現れます。
