Video generation · Diffusion · Prompt design

動画拡散モデルのプロンプトは motion を構造化する。

テキストから動画を生成する拡散モデル（MiniMax-H3 など）で、意図した映像を出すためのプロンプトの体系的な書き方を整理する。 静止画プロンプトの延長ではなく、「何が時間とともに変化するか」を motion として第一級の要素に構造化するのが本質。 5要素・カメラ3次元・ショットブロック・モデル別の違い・パラメータ実践・落とし穴をまとめる。

対象 MiniMax-H3 / 動画拡散モデル 出典 ローカル推論（mlx-serve）の実践知 確認日 2026-08-11 環境 Apple Silicon M5 Max / mlx

核心の一文

動画プロンプトは「何が時間とともに変化するか」を明示しないと、静止画の延長でしかない。 静止画プロンプトに「動き」の記述を足すのではなく、motion を第一級の要素として構造化するのが動画生成の本質である。

動画プロンプトの 5 要素（ここだけ覚える）

1. identity recipe ── 被写体の見た目・属性の「レシピ」。人物なら年齢・髪型・服装・表情の基準。静止画と同じ。
2. environment ── 背景・場所・時間帯・天候。被写体と環境の関係（前景/背景）も含む。
3. motion ── 動きの記述。動画固有の最重要要素。
4. lighting ── 照明・光の質。キーライト、逆光、色温度、時間帯による光の変化。
5. grading ── 画調・トーン。フィルム調、シネマティック、コントラスト、彩度。

順序は「何が写っているか → どう動くか → どう光るか → どう仕上がるか」の流れで書くと自然にまとまる。 以下のセクションは、この 5 要素のうち特に動画固有の motion を中心に、実践で効く順に並べたもの。

motion が最重要

動画生成で最も失敗するのは「動きが足りない」「動きが意図と違う」こと。motion は次の 4 つの軸で明示する。

  • カメラ移動 ── パン・チルト・ドリー・ズーム・手持ち。カメラがどう動くか。
  • 被写体アクション ── 被写体が何をするか。歩く、振り返る、手を伸ばす、といった具体的な動作。
  • 環境の動き ── 風、水、煙、葉の揺れ、粒子。背景の動きが「生きている」印象を作る。
  • ペーシング ── 全体のテンポ。ゆったりか、疾走感か。時間軸の密度。

「静かな森で少女が歩く」だけでは動きが曖昧。次のように書くと意図が伝わる。 

カメラはゆっくりとドリーインし、少女は振り返って微笑む。
風で木々の葉が揺れ、川の水面がきらめく。全体はゆったりとしたペーシング。

カメラモーションの 3 次元

カメラの動きは 3 つの軸で指定すると、モデルが再現しやすい。

  • モーションタイプ ── パン（横振り）/ チルト（縦振り）/ ドリー（前後移動）/ トラック（横移動）/ ズーム / 手持ち。
  • 振幅 ── 動きの大きさ。微細な揺れか、大胆な移動か。
  • 速度 ── 速さ。ゆっくり / 中速 / 速い。

例: 「手持ちカメラ、振幅は小さく、ゆっくりとした速度で被写体を追う」のように 3 軸を揃えて書く。 1 軸だけ（「パン」）だと振幅と速度がモデル任せになる。

3 軸を揃えると再現性が上がる

タイプ・振幅・速度の 3 つを明示すると、モデルがカメラの動きを独立に制御しやすくなる。 どれか 1 つが欠けると、残りはモデルのデフォルトに委ねられ、意図とズレやすい。

ショットブロック単位の構成

長い動画は「ショットブロック」単位で組み立てる。1 ブロック = 1 つのカメラアングル + 1 つの連続した動き。 ブロックごとに「何が時間とともに変化するか」を 1 文で説明する。 

ショット1: 広角。カメラは固定。被写体が画面右から左へ歩き、背景の雲がゆっくり流れる。
ショット2: 中景。カメラはドリーイン。被写体が振り返り、表情が和らぐ。
ショット3: クローズアップ。カメラは手持ち。被写体の手が画面外へ伸びる。

各ブロックで「変化するもの」を 1 つに絞ると、モデルの負担が減り、意図が安定する。 複数の動きを 1 ブロックに詰めると崩れやすい。

モデル別の違い（MiniMax-H3）

モデルごとにプロンプトの解釈が異なる。MiniMax-H3 を例に、知っておくべき構造を整理する。

4 つの生成モード

モード入力用途
T2VAテキスト → 動画テキストだけで動画生成
I2VA画像 + テキスト → 動画静止画を動かす
FL2VAフレーム列 + テキスト → 動画複数フレームから補間
L2VA音声 + テキスト → 動画音声に合わせた動画生成

3 コアフィールド

MiniMax-H3 はプロンプトを複数のコアフィールドに分解して解釈する。被写体・環境・動きを別々のフィールドに割り当てると、 モデルが各要素を独立に制御しやすくなる。

話者 ID

L2VA モードでは話者 ID を指定できる。複数話者の会話シーンで、誰が話しているかを明示すると口元の動きと音声が揃いやすい。

パラメータの実践

プロンプトと同じくらい、生成パラメータが結果を左右する。実践で重要なものを挙げる。

  • steps ── 推論ステップ数。多いほど精細だが時間がかかる。品質と速度のトレードオフ。
  • CFG / guidance ── プロンプトへの忠実度。高すぎると過剰・破綻、低すぎるとプロンプト無視。モデル推奨値から微調整。
  • seed ── 乱数シード。同じシードで再現性を取れる。失敗した生成のシードを固定して微調整する。
  • フレーム数 ── 動画の長さ。フレーム数 = 秒数 × fps。長いほど生成時間とメモリが増える。
  • 解像度の 32 倍数制約 ── 多くのモデルは幅・高さが 32 の倍数を要求する。例: 704×480 = 22×32 / 15×32。32 の倍数でないとエラーになる。
# 例: 704x480, 10秒(240f), 24fps 相当
width=704  height=480  frames=240  steps=30  cfg=7.0  seed=42

32 倍数制約を守らないとエラー

幅・高さが 32 の倍数でないと、多くのモデルは生成を拒否する。解像度を決める前に width % 32 == 0 と height % 32 == 0 を確認する。

落とし穴

実践で踏みがちな罠をまとめる。

  • Negative prompt はモデルによって効かない ── 一部の動画モデルは negative prompt を無視する。効くかどうかはモデル仕様で確認し、効かない場合は「避けたい要素」を positive 側に明示する。
  • 60fps → 24fps ダウンサンプル ── 生成が 60fps でも、映画的な見た目には 24fps へダウンサンプルする。フレーム間引きで滑らかさと「映画感」のバランスを取る。
  • 4〜6 秒生成が基本 ── 一度に長い動画を生成すると品質が落ちる。基本は 4〜6 秒単位で生成し、ショットブロックを連結して長尺を作る。

覚えておく 1 行

動画プロンプトは「静止画プロンプト + 動き」ではなく、motion を構造化した 5 要素で書く。 カメラは 3 軸、長尺はショットブロック単位、パラメータは 32 倍数制約と 4〜6 秒生成を守る。
